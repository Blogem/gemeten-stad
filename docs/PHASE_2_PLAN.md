# Phase 2 plan — extraction, fulfilment, and campaign-level matching

Phase 1 delivered a **working coverage audit from structure alone**: permits harvested, resolved,
assembled, and linked to registry fellings with confidences, with *"no matching source found"* as a
first-class provenanced finding. It deliberately stops at *"which fellings does this permit cover?"*.

Phase 2 answers the next question — **"and was the herplantplicht met?"** — which needs three
things Phase 1 does not have: the permit's own **obligation count** (extraction), the registry's
**replant** half in the graph, and a matching model that treats a permit as **one bounded felling
campaign** rather than a bag of individually-assigned trees. See `IMPLEMENTATION_PLAN.md` §6 for
where Phase 2 sits; this file decomposes it into independently-tackleable work items, in the same
shape as `PHASE_0_PLAN.md` / `PHASE_1_PLAN.md`. **Each P-item is sized to become one OpenSpec
change.**

## What changed from the one-line Phase-2 scope

`IMPLEMENTATION_PLAN.md` §6 originally scoped Phase 2 as *"extraction"* — the three-tier
`msr-graph` extractor from Spike C. Building Phase 0/1 added three more things that belong here,
all now folded in (and one that was pushed out):

- **The fulfilment axes land here, as one unit.** Phase 1's `derive` is coverage-only; the
  multi-axis fulfilment of §"Fulfilment" (estimate / timeliness / caveats / confidence, tracked
  bitemporally) is only meaningful against an extracted obligation count, so it is built once,
  coherently, alongside extraction — P22/P24.
- **The replant layer comes with it.** `model-felled-trees` deferred `gs:Replanting` /
  `gs:plantedTree` / `gs:plantedOn` + the felled→replacement lineage to Phase 2 *as one coherent
  unit* with the fulfilment `Assessment`, on the grounds that a replant event is worthless without
  the felling it discharges (that change's D6). P17.
- **The matching model gets reworked, not extended.** P15's acceptance gate measured **42.6%**
  exclusive match against **92.3%** candidate existence: ~50% of permits had candidate fellings and
  lost every one of them to a competing permit under the greedy per-felling assignment, and a
  matched permit can "cover" fellings years apart (`DATA_THREAD_NOORD.md`'s `Z2022-N001404` spans
  2023-01 → 2025-02). Phase 2 replaces the per-felling greedy with **permit↔cluster matching,
  count-constrained** — P18 (probe) + P23 (rework).
- **Decision periods (Verlenging / Rectificatie).** P13 found that one zaak often carries several
  publications; v1 assembles only the primary besluit, so an *extended or rectified* term is
  invisible above the value store (`IMPLEMENTATION_PLAN.md` §3, "multiple decisions per case").
  Anything keyed on the original besluit's dates misjudges those cases. P19.
- **Pushed out:** the `gebrekregistratie` / `boomgebreken` ingest (and its SKOS concepts) stays
  deferred — see "Explicitly out of scope" below.

Two traps worth restating because they have already bitten: the `ingest/koop/testdata/*.xml`
fixtures are minimal and omit geometry + the metadata sidecar — **validate against `data/raw/koop/`,
never the fixtures**; and the abstract *is* the document's Omschrijving line, so **there is no
per-document body fetch** for extraction (Spike C Finding 4: the body injects boilerplate noise and
makes counts *worse*).

## Recommended sequencing

- **Wave A — independent starts (need only Phase-1 output):** P16 `extract koop` deterministic
  floor · P17 replant layer · P18 Probe F (clustering half starts now; its count-constrained half
  waits on P16) · P19 decision periods. Four genuinely parallel items touching four different
  packages.
- **Wave B — the extractor's upper tiers + the obligation (needs P16):** P20 spaCy recognition ·
  P21 LLM binder (needs P20) · P22 obligation quantity + diameter-class equivalence.
- **Wave C — the audit rework (needs the probe + the count):** P23 cluster matching, then P24
  fulfilment `Assessment`.
- **Wave D — growth loop:** P25 vocabulary mining (can slip past the gate; it improves recall, it
  does not unblock anything).
- **Wave E — the gate:** P26 end-to-end on the real Noord corpus + write-up.

**Hard gates:** **P16** blocks P20/P21/P22 (everything needs the extraction store and the floor);
**P18** blocks P23's *design* (do not design the matcher before the cluster shape is measured);
**P23** blocks P24's numbers (fulfilment is computed per matched campaign).

## P16 · `extract koop` — the deterministic count floor (Go) + the extraction store

- **Goal:** Per-activity obligation counts out of the permit abstract, into a durable re-readable
  extraction store, with **zero NER/LLM dependency** — the offline floor the whole audit can fall
  back to.
- **Entails:** reimplement `spikes/spike-c/parse_activities.py` in Go under `extract/koop` (§5:
  Go everywhere except spaCy), reusing/creating `extract/shared`: clause splitting on `en`/`,`,
  verb→count binding, spelled-out Dutch numerals (`een`…`twintig` plus compounds like
  `vierenveertig`), the `boom` / `bomen` / **`houtopstand`** nouns, and — the correctness point, not
  just the yield point — a **per-activity split then sum** over {kappen, vellen, rooien,
  **verplanten**}, with herplant/planten kept strictly on the **replant** side and never in the
  obligation. Reads the landed publications (never re-fetching bodies). **Zaaknummer-level count
  resolution:** take the count from **whichever doctype carries it** — an aanvraag sometimes states
  a count its besluit omits (Spike C scope note) — and record which publication supplied it; the
  audited entity stays the besluit.
- **The extraction store (new):** a PostGIS table (e.g. `permit_extractions`) keyed by zaaknummer,
  holding per-activity counts, the obligation total, the **tier** that produced it, the source
  publication id + span offsets, the model/prompt version, and `extracted_at` — plus the durable
  cache directory from `dump/doc.go` D4 for the tiers that follow. **Counts are values → PostGIS,
  never RDF literals** (`RDF_MODELING.md` §1); see "Modeling decisions" below.
- **The doc-type seam (settled decision — build it, don't use it):** parser selection is a
  **registry keyed by publication type**, so a newly-discovered permit document type is a new
  registered parser + its fixtures, not a rewrite of the extractor. Phase 2 registers **only** the
  kap besluit/aanvraag pair; no second doc type is implemented here (see "Explicitly out of scope").
- **Key decisions:** the extraction row's grain (per zaaknummer vs per publication — recommend per
  publication rows with a per-zaaknummer resolved view, so "which doctype gave the count" is data,
  not a comment) · wiring the `extract` subcommand (a stub today) into `cmd/pipeline` · whether the
  store or the cache is authoritative on a re-run (recommend: cache authoritative for tier output,
  table authoritative for the resolved count).
- **Done when:** yield reproduces Spike C on the real corpus (**≥72%** of citywide besluiten,
  **≥73%** Noord) with the per-activity split; the **32** known naive-conflation cases resolve
  correctly (e.g. `vellen 33 + verplant 43 → 76`, not `43`); a herplant count never enters an
  obligation total; re-running is a no-op (cache hit, no rewritten rows); table-driven tests over
  the spike's labeled cases and the easy half of `gold_labels.py`.
- **Depends on:** P11/P13 (landed publications + `koop_publications`), P9 (`dump` cache contract).

## P17 · Replant layer — `gs:Replanting` + the felled→replacement lineage

- **Goal:** Project the registry's **replant** half into the graph, so fulfilment has an observed
  fact to test the obligation against.
- **Entails:** extend `load/bomen`'s graph projection (which today emits felled `gs:Tree` +
  `gs:Felling` only). For a felled row with `plantmaatregelDatumUitgevoerd` set: mint
  `gs:Replanting` (`data:replanting/<kapenherplant-id>`) with `gs:plantedTree` → the **replacement**
  `gs:Tree` (`data:tree/<boomNieuwId>` — `boomId ≠ boomNieuwId`, a replacement is a *new distinct*
  tree) and `gs:plantedOn` (`xsd:date`, an immutable descriptive literal exactly like
  `gs:felledOn`), plus the **tree-level lineage** `felled tree dct:isReplacedBy replacement tree`.
  **Settled** (`model-felled-trees` D6): reuse `dct:isReplacedBy`, at the *tree* level — **not** a
  minted `gs:replaces`, **not** event-to-event (an event doesn't supersede an event; the *tree* is
  what's replaced). Where a felling has no replant, **mint nothing** — absence is read as absence
  (the ~126 unmet Noord fellings), never as a false or empty node. Bulk registry values
  (`boomAanwezigheid`, species, geometry) stay in PostGIS.
- Add the TBox terms + `rdfs:label`/`rdfs:comment` and a `ReplantingShape` to `shapes.ttl` (a
  `gs:Replanting` missing `gs:plantedTree` or `gs:plantedOn` must not enter the graph).
- **Key decisions:** how a replanting connects to the felling it discharges — via the tree lineage
  (`felled tree dct:isReplacedBy new tree`, whose `gs:Replanting` names it) rather than a direct
  event→event edge · what to do with `boomAanwezigheid = "Ja, nieuwe boom reeds aangeplant"` rows
  that carry **no** `boomNieuwId` (recommend: no `gs:Replanting` node — an unidentified tree is not
  an identity; record it as a caveat on the assessment instead) · **replacement-then-refelled
  chains** (rare: 52/7,223) — a replacement tree may itself carry a `gs:Felling`; the model already
  permits it, the tests must pin it.
- **Done when:** the Noord replant rows project and reconcile with the PostGIS counts; a felling
  without a replant yields no `gs:Replanting`; a refelled replacement chains correctly; re-running
  is a no-op; SHACL rejects a malformed `gs:Replanting`; the `dct:isReplacedBy` lineage is
  traversable felled→replacement.
- **Depends on:** P7 (registry in PostGIS), `model-felled-trees` (`gs:Tree`/`gs:Felling`), P12
  (graph writer).

## P18 · Probe F — what a felling campaign actually looks like (data probe, **before** the matcher)

- **Goal:** Settle **with data, before designing the matcher**, what spatial-temporal felling
  clusters exist in `kapenherplant` and whether permit↔cluster is 1:1. `IMPLEMENTATION_PLAN.md` §6
  flags this as the open question; the matcher design is blocked on the answer.
- **Entails:** a throwaway probe (`spikes/spike-f/`, same discipline as Spikes A–E) that clusters
  Noord fellings (with a citywide control) by **space and time** — sweep the parameter grid
  (distance ~25 / 50 / 100 / 200 m × window ~30 / 90 / 180 / 365 days; DBSCAN-ish or connected
  components) and report the cluster-size distribution and each cluster's temporal spread. Then,
  against the 659 Noord permit anchors and P16's counts, quantify the four cardinality cases:
  (a) permits whose count matches a **whole** cluster, (b) permits needing a correctly-sized
  **slice** of one, (c) clusters spanning **multiple** permits, (d) permits spanning **multiple**
  clusters. Explain the ~50% "outcompeted" cohort in these terms.
- **Test the cheap alternative first:** the registry carries work-order codes
  (`deelopdrachtGroeiplaats` / `deelopdrachtPlanten`) and `projectnaamBomen` /`selectiecode`. The
  latter two are 0% populated in Noord (Spike B), but the **deelopdracht codes have never been
  probed** — if a work-order code groups fellings into campaigns, that is a *near-key* and beats
  geometric clustering outright. Check this before tuning any distance parameter.
- **Done when:** recommended clustering parameters are chosen **with evidence**; the 1:1 question is
  answered with numbers, not an assumption; the deelopdracht-as-key hypothesis is confirmed or
  killed; the findings are written up (and folded back into `DATA_SOURCES.md` §2a if the codes turn
  out to carry signal).
- **Depends on:** P7; P16 for the count-constrained half (the clustering half can start immediately).

## P19 · Decision periods — Verlenging / Rectificatie / Ingetrokken in the graph

- **Goal:** Close the gap recorded in `IMPLEMENTATION_PLAN.md` §3: the graph shows one immutable
  besluit per case, so an **extended, rectified, or withdrawn** decision looks exactly like its
  original — and any elapsed-time or legal-force reasoning misjudges it.
- **Entails:** read the retained publication trail in `koop_publications` (one row per publication,
  title-prefixed kind: Aanvraag / Besluit / Verlenging / Rectificatie / Ingetrokken /
  Ontwerpbesluit) and model the decision's **legal force** as validity-stamped state on the audited
  `Intervention`: `gs:LegalStatusPeriod` (class exists, unused) via `gs:versionOf` a stable anchor,
  with `gs:validFrom`/`gs:validTo` and a controlled status value. Exactly one open period per
  anchor; a change **closes** the prior and opens a new one, never overwrites. The `Intervention`
  IRI stays the primary besluit's zaaknummer — **identity does not move** when the term is extended.
- **Key decisions:** *status periods on one intervention* vs *a decision entity per publication
  linked `amends`/`supersedes`* — recommend status periods (leaner; the zaaknummer *is* the case
  identity), but if entity-per-publication wins, reuse **`prov:wasRevisionOf`** rather than minting
  a `gs:amends` · the status value set (in-force / extended / rectified / withdrawn) as SKOS
  concepts under the legal top with `dct:source` the publication kind, reusing the existing
  `gs:status` property · **whether `Ingetrokken` suppresses the claim** — it arguably should (no
  felling right → no herplantplicht), which means an already-derived `AuditLink` needs a defined
  interaction; decide explicitly rather than letting it fall out of the code.
- **Done when:** cases carrying a Verlenging show ≥2 `gs:LegalStatusPeriod`s with exactly one open;
  withdrawn cases are identifiable and their treatment in fulfilment is deliberate and documented;
  re-running is a no-op; SHACL gates the period shape; the number of affected Noord cases is
  reported (so the size of the gap is on record).
- **Depends on:** P13 (the publication trail), P12, P8 (ontology/vocab).

## P20 · `extract/ner` — recognition tier: a spaCy EntityRuler seeded from the SKOS graph (Python)

- **Goal:** Lift obligation-count recall **83% → 90%** by recognizing the count shapes a boom-only
  parser cannot see, and extract the **species / project** residue that exists *only* in the prose
  (the registry is 0% populated on both).
- **Entails:** build out the `extract/ner` Python package (stub + `pyproject.toml` exist): a
  **`graph_reader`** that SPARQLs the loaded vocab for concepts + `skos:prefLabel`/`skos:altLabel`
  and emits EntityRuler patterns carrying the **concept IRI in `id`** (read back via `ent_id_`) —
  the `msr-graph` `graph_reader → seeding` shape; `nl_core_news_md`; a small Dutch number
  normalizer (compound numerals); count binding over the dependency parse. Recovers
  species-headed counts ("drie essen"), compound numerals, and singular implicit-1 ("Kappen Ceder")
  — **146/340** of the deterministic residual. Results go into P16's extraction store and the
  durable NER cache (keyed doc id + model/prompt version).
- **No hardcoded species or plural tables** — the vocab supplies every surface form. This is the
  architectural point: `nl_core_news_md`'s lemmatizer is too weak for botanical morphology
  ("essen"→"Essen", "iepen"→"ie", "berken"→VERB), so recognition rides on **vocab altLabels**, and
  the vocab already carries ~185 genus tops + ~1.5k cultivars with authored plurals. Growing it is
  P25's job, not a code change — and that must be *tested*, not merely intended.
- **Species / project into the graph:** assert `gs:species` → the species concept (term exists) with
  an RDF-star `{| gs:confidence ; gs:evidence |}` annotation, and mint `gs:Project` +
  `gs:partOfProject` for a recognized project (both terms exist; sparse by design — ~1.3% of
  abstracts). Per-span provenance: see "Modeling decisions" — the span *offsets* are values and
  belong in PostGIS; the graph carries `prov:wasDerivedFrom` the publication.
- **Key decisions:** the Go↔Python boundary (subprocess CLI over JSONL vs a small local HTTP
  service — recommend the subprocess: no service to run, matches the batch pipeline) · whether the
  recognizer reads the vocab from Fuseki live or from a generated pattern file refreshed on vocab
  change (recommend live-from-graph, which is the whole point of graph-seeded patterns).
- **Done when:** obligation-count recognition reaches **≥90%** on the Spike-C measurement set and
  the 146/340 residual recovery reproduces; **adding an altLabel to the vocab changes recognition
  with no code change** (an explicit test); a re-run is a cache hit with zero model invocations;
  species/project assertions carry confidence + provenance and pass the SHACL gate; a pytest suite
  covers the graph_reader, the number normalizer, and the binder.
- **Depends on:** P16 (store + floor), P8 (vocab in the graph), P9 (cache contract).

## P21 · LLM count-binding — selective escalation behind a provider interface

- **Goal:** Recover the hard tail (**44% → 95%** exact match on the 80-case gold set) without paying
  for the whole corpus, and without the audit ever *depending* on an LLM.
- **Entails:** the **escalation policy as a first-class, testable predicate** — escalate iff
  (tiers 1–2 **disagree**) **or** (a felling permit yields **no** count) **or** (a hard-shape flag
  fires: multi-activity / appositive / snoeien-mixed / "waarvan" / "of"). Where the two cheap tiers
  **agree, take the count as-is** — justified by measurement, not thrift: on the 100 easy agreeing
  cases the LLM matched 98/100 and added 2 abstentions, so escalating them **loses** accuracy.
  Target ~**14%** of felling permits escalating. A closed-set prompt constrained by the recognized
  activity/species IRIs; strict JSON validated against that closed set; **abstention or malformed
  output falls back to the deterministic floor** (~7% abstention observed) and the fallback is
  recorded, not hidden.
- **Provider (settled): behind a small interface, with DeepSeek as the default.** The key and model
  come from the environment (`LLM_MODEL_EXTRACT` + the API key), **never a file**. The interface
  earns its keep — it is not speculative flexibility: it keeps the model swappable, gives tests a
  fake with no network, and makes re-validating against `gold_labels.py` a config change rather than
  a rewrite. Every binding records the **model id + prompt version** in both the cache key and the
  extraction row, so a run is reproducible and a model bump is a distinct cache entry rather than a
  stale hit (the `dump/doc.go` D4 contract, exactly as designed).
- **Key decisions:** prompt versioning scheme (must be part of the cache key) · whether escalation
  runs inline in `extract` or as a separate pass over flagged rows (recommend inline, one stage) ·
  the abstention/retry budget.
- **Done when:** **≥90%** exact match on `spikes/spike-c/gold_labels.py` with the default provider
  (Spike C measured 95%; report the actual); escalation rate on the Noord corpus is **measured** and
  ≤~20% of felling permits; no regression on the easy agreeing set; **a cached re-run makes zero
  LLM calls** (verified with the network blocked); the abstention→floor path is tested; the
  interface ships a fake used by the unit tests.
- **Depends on:** P16, P20.

## P22 · The obligation quantity — `Claim` gains a size, and diameter-class equivalence

- **Goal:** Turn an extracted felling count into the **legal obligation quantity** the fulfilment
  fraction divides into. "The obligation is a computed quantity, not 1:1" (§2) — this is where that
  becomes real.
- **Entails:** transcribe the **diameter/age-class equivalence** from the beleidsregel *Compensatie
  en herplant van bomen* (CVDR697591) into an explicit rules table, **per-rule `dct:source` to the
  article it comes from** (a legal reading, so it is sourced and reviewable, never inferred). The
  age-class SKOS concepts already exist (`con:leeftijdsklasse-*`). Read the felled trees' class from
  `stamgegevens` (PostGIS) where known; where unknown, compute the **1:1 floor** and flag it rather
  than guessing. `transplantOrigin` fellings count **into** the obligation total (Spike C: art. 1k
  makes verplanten a velling), carrying the caveat.
- **The quantity is a number, so it lives in PostGIS** — keyed by the Claim IRI (its own table or an
  extension of `audit_metrics`). The graph carries the Claim's identity, the **class concept(s)** it
  references (meaning, not values), the `gs:countUnknown` caveat where there is no count, and
  provenance (`prov:wasDerivedFrom` the extraction; `dct:source` the beleidsregel). This applies
  `RDF_MODELING.md` §1 strictly and needs ratifying, because §"Fulfilment" describes the Claim in
  prose as *"N trees of class C at place L"* — see "Modeling decisions" below.
- **Key decisions:** where the equivalence is applied (obligation side only — the registry's replant
  count stays raw and observed) · how a mixed-class felling set aggregates · whether an unknown
  class yields `1:1` + a caveat or no quantity at all (recommend the flagged 1:1 floor: an
  under-estimate that is *stated* beats a blank).
- **Done when:** the rules table is transcribed with per-rule article sources and reviewed; every
  permit with a count has an obligation quantity, and every permit without one is marked
  `countUnknown`; class-unknown falls back to the flagged 1:1 floor; unit tests cover the
  equivalence table and both fallbacks; **the quantity appears nowhere as an RDF literal.**
- **Depends on:** P16 (counts), P7 (`stamgegevens` classes), P8 (vocab/ontology).

## P23 · `derive` — felling-cluster matching replaces the greedy per-felling assignment

- **Goal:** A permit is **one bounded felling campaign**. Match permits to **clusters** — or the
  correctly-sized **slice** of one — count-constrained, replacing the per-felling greedy assignment
  that produces both the implausible multi-year "coverage" and the ~50% outcompeted no-source cohort.
- **Entails:** three pieces.
  1. **Cluster the fellings** (space + time) into candidate blocks using the parameters Probe F
     justified — or the registry work-order key, if P18 finds one that beats geometry+time.
  2. **Replace D6(2)'s exclusive per-felling greedy with record-linkage-with-blocking** — clusters
     are the blocks. Score permit↔cluster on place + time + **count** (the axis that is inert today:
     `coverage.go` passes `PermitCount: nil`, while `score.go` already implements the ±15%
     compatibility term — P16/P22 supply the value) + ambiguity. Permit a permit to take a
     correctly-sized **slice** of a cluster, and honour the cardinality Probe F actually measured —
     **do not assume group↔permit is 1:1**.
  3. **Re-calibrate the place term.** `score.go`'s `placeTerm` caps postcode-tier proximity at 0.70
     and floors it at 0.50, so a postcode-resolved permit can never out-score a nearby address-tier
     one — postcode-tier permits match at **1.4%** (2/145). Recalibrate with the count axis live and
     re-measure per tier; P15 flagged both effects as design follow-ups, and this is where they land.
- **The recording model does not change** — a good sign P14 got it right. The `gs:Observation` stays
  content-addressed by its assigned felling set; `gs:AuditLink` anchors and `gs:CoveragePeriod`
  versioning are untouched. Only the *matching unit* changes.
- **This is a rework in place, not a v2.** Delete the greedy path; no `if legacy` fallback, no
  parallel scorer (project rule: no optional paths "just in case").
- **Key decisions:** whether a cluster becomes a **graph node** or stays derivation-internal — see
  "Modeling decisions"; recommend derivation-internal (PostGIS) unless Probe F shows clusters are
  stable enough to carry an IRI · slice semantics (which fellings of an over-sized cluster a permit
  takes, and how the remainder is offered to other permits) · whether an unmatched *cluster*
  deserves its own finding (the registry→permit direction: fellings with no permit at all — a
  genuinely interesting audit signal, and cheap once clusters exist; scope it explicitly in or out).
- **Done when:** **no matched permit covers fellings spanning more than the campaign window Probe F
  justified** — `Z2022-N001404`'s 2023-01 → 2025-02 span is the named regression case to kill, and
  the worst remaining span is reported; the three-metric picture is re-reported (candidate existence
  / exclusive match / genuine no-source) with the outcompeted cohort materially reduced *and
  explained*; the per-tier match table is re-measured (postcode tier especially); `derive` is still
  a true no-op on unchanged input; scoring and slice logic are unit-tested against the probe's
  labeled cases; an integration test covers a seeded permit + cluster subset.
- **Depends on:** P18 (parameters + cardinality — a hard gate on the *design*), P16/P22 (the count),
  P14 (the code being reworked).

## P24 · `derive` — the multi-axis fulfilment `Assessment` (bitemporal)

- **Goal:** Deliver §"Fulfilment" in full: **don't collapse to "indeterminate"** — estimate on every
  axis the evidence supports, and track the verdict through time without ever overwriting it.
- **Entails:** per `Claim`, open a `gs:Assessment` (class declared, never written — Phase 2 models
  its properties) carrying four axes:
  - **fulfilment estimate** — `none` / `partial` / `fulfilled`, from observed replant (P17) vs the
    computed obligation (P22). The **fraction is a number → PostGIS**; the graph carries the
    estimate *term*.
  - **timeliness** — `notYetDue` / `onTime` / `overdue` / **`deadlineUnknown`**, the last being the
    default for almost every claim (Spike A: the termijn lives nowhere publicly reliable;
    `datumAfrondenVoor` is rejected). Any elapsed-time signal anchors on
    `kapmaatregelDatumUitgevoerd`, never a batch-assigned permit date, and a long-overdue flag is an
    **advisory caveat, not a hard `overdue`**.
  - **caveats** — `fundEligibilityUnknown` (new), `deadlineUnknown` (new), plus the existing
    `weakLink` / `transplantOrigin` / `countUnknown`. They qualify the estimate; they never erase it.
  - **confidence** — inherited from the coverage link the whole assessment rests on.
- **The registry↔permit count cross-check** — the external triangulation that catches
  under-reporting: the registry's felled count for the matched campaign vs the permit's own
  extracted count. A discrepancy is recorded as **its own finding**, not silently absorbed into a
  confidence score. (This is the leg that only becomes possible once extraction exists.)
- **Bitemporal open/close:** SCD-2 via `gs:versionOf` an anchor + a **content-derived** period IRI
  (the settled pattern — an unchanged re-run is a true no-op), `gs:validFrom`/`gs:validTo`, one open
  assessment per anchor. A claim that is now `fulfilled` **retains its earlier `partial` assessment
  in history**, with the interval it held.
- **Key decisions:** the estimate/timeliness value shape — small model-level enums bound by `sh:in`
  (the `gs:granularity` precedent) vs SKOS concepts in the vocab (see "Modeling decisions";
  recommendation there) · when `fundEligibilityUnknown` applies (recommend: every "no replant
  observed" case — herplantfonds discharge is legitimate and not publicly observable, §2) · the
  narrow definition of true `indeterminate` (no usable link at all) and a measured expectation that
  it is the **minority**, not the default.
- **Done when:** every Noord claim with a coverage link carries an Assessment on all four axes, and
  **no claim collapses to a bare `indeterminate` where any axis was computable**; a changed registry
  state closes the prior assessment and opens a new one with history retained and exactly one open
  per anchor; the cross-check emits discrepancies as findings; SHACL rejects an assessment missing
  its estimate/confidence (and a `partial` with no fraction reference); re-running is a no-op; the
  §"Fulfilment" target reading — *"partial (9/18), deadline unknown, fund-eligibility unknown, link
  confidence 0.8"* — is reproducible for a real Noord permit straight from the graph + value store.
- **Depends on:** P17 (replant layer), P22 (obligation), P23 (matched campaigns), P19 (extended /
  withdrawn cases), P12.

## P25 · The vocabulary mining loop — altLabel proposals, human confirmation

- **Goal:** Keep recognition improving **without code changes** — the "living vocab" recipe (§3):
  seeded from authoritative sources, grown from the corpus.
- **Entails:** an offline loop that mines surface-form candidates (noun chunks, abbreviations,
  cultivar phrasings, "t.h.v.") from the Noord + citywide abstracts that the vocab does not yet
  cover, has an LLM **propose** concept↔surface mappings, and writes them to a **proposal artifact
  for human confirmation** — nothing enters the vocab unconfirmed. Confirmed labels are folded into
  `ontology/generate_vocab.py`'s output and `ontology/vocab.ttl` is regenerated and committed (it is
  a checked-in artifact, not rebuilt per run). This also lands the growth item the vocab header
  already records as deferred ("corpus-mined surface variants — Phase 2").
- **Key decisions:** where confirmed labels live so regeneration is reproducible (a checked-in
  curation file read by `generate_vocab.py`, not hand-edits to the generated turtle) · ranking
  proposals by corpus frequency × recognition impact.
- **Done when:** a run produces ranked proposals with corpus evidence and counts; confirming a batch
  and regenerating the vocab **measurably lifts P20's recall on a held-out slice** (the loop is
  proven, not assumed); nothing reaches the vocab without human confirmation; the loop is documented
  as a repeatable chore.
- **Depends on:** P20, `ontology/generate_vocab.py`.

## Modeling decisions to settle (RDF) — raise these in each change's design

`RDF_MODELING.md` §9's per-change checklist applies to every item that touches the graph, and SHACL
is the gate: a modeling change isn't done until it validates. Six decisions are worth naming up
front, because they are exactly the places Phase 2 could quietly go wrong.

1. **The obligation count and the fulfilment fraction must stay out of RDF — ratify this
   explicitly.** `RDF_MODELING.md` §1 is unambiguous: *"Every quantitative value — tree counts,
   polygons, replant fractions — lives in the value store, never as an RDF literal. A class or
   property that looks like it wants a number is a modeling error."* But §"Fulfilment" describes the
   `Claim` in prose as *"N trees of class C at place L"* and the estimate as `partial(fraction)`,
   which reads like literals. **Recommended shape:** the graph carries the `Claim`'s identity, the
   **class concept** it references (`con:leeftijdsklasse-*` — meaning, legitimately graph-side), the
   caveats, and provenance; the **numbers** (per-activity counts, obligation quantity, observed
   replant count, fraction) live in `permit_extractions` / `audit_metrics`, reached from the graph
   via the Claim IRI. Ratify or overturn this in P22's design — do not let it be decided implicitly
   by whichever code lands first.
2. **Extraction span provenance — reuse before minting, and check whether the graph needs the span
   at all.** Spike C's tier-2 note says "per-span provenance into the graph". The established
   standards for text spans are **W3C Web Annotation** (`oa:Annotation` +
   `oa:TextQuoteSelector`/`oa:TextPositionSelector`) and **NIF 2.0** — either is preferable to a
   minted `gs:` span term if spans belong in the graph. **Recommended:** character offsets are
   values → PostGIS (the extraction row already holds them); the graph asserts
   `prov:wasDerivedFrom` the publication plus the generating `prov:Activity` (which tier, which
   model/prompt version — transaction time is already PROV). Adopt `oa:` **only** if the webapp
   needs to highlight the span from graph data alone. Decide in P20's design and record the
   rejected alternative.
3. **`gs:Assessment`'s axis values: model enum or SKOS concept?** The `gs:granularity` precedent is
   a *"fixed, small, model-level enum (label only, no class or SKOS scheme), bound by `shapes.ttl`
   `sh:in`"*. **Recommended for the fulfilment axes: SKOS concepts in the vocab**, not bare model
   enums — unlike `granularity` (an internal implementation tier), `none`/`partial`/`fulfilled` and
   the timeliness values are **domain meaning the agent must ground and cite**, they derive from the
   regulation, and the vocab exists precisely to ground the agent. Trade-off to state: this is
   heavier than `granularity`'s pattern and slightly inconsistent with it — justified because the
   two sets differ in kind, not because SKOS is nicer.
4. **A felling cluster: graph node or derivation artifact?** Tempting to reuse `gs:Project` (a
   campaign ≈ a project, which `DATA_THREAD_TREES.md` argues for) — but a *derived* cluster is not
   the same thing as a *named renewal project*, and conflating them would give one IRI two
   meanings, which the IRI policy forbids. Clusters also **change as registry data arrives**, so a
   mutable cluster node is a versioning hazard. **Recommended:** keep clusters derivation-internal
   (PostGIS) unless Probe F shows they are stable and independently useful; if they must be graph
   nodes, **content-address them by member felling set** (the `gs:Observation` precedent) and keep
   them distinct from `gs:Project`.
5. **New caveat terms + a stale definition to fix.** P24 adds `gs:fundEligibilityUnknown` and
   `gs:deadlineUnknown` as `gs:Caveat` individuals — and `shapes.ttl`'s `sh:in` list, currently
   bound to exactly the five existing individuals, must grow with them (otherwise the gate rejects
   valid assessments). Separately, **`gs:countUnknown`'s `rdfs:comment` becomes wrong in Phase 2**:
   it reads *"the permit's stated tree count is unknown (Phase 1 does not extract permit-text
   counts)"*. The IRI keeps its meaning (the count is unknown *for this permit*); the **definition
   must be rewritten** to drop the Phase-1 rationale. Updating a term's documentation is correct;
   repurposing its meaning would not be.
6. **Settled, don't re-litigate:** the replant lineage is **`dct:isReplacedBy` at the tree level**
   (reuse-first; not a minted `gs:replaces`, not event-to-event) — `model-felled-trees` D6. Confidence
   and evidence use the `{| … |}` annotation form, never bare `<< … >>`. Period nodes carry plain
   `gs:confidence`/`gs:evidence` (there is no base edge to annotate) — the `gs:CoveragePeriod`
   precedent, which `gs:Assessment` should follow. **No GeoSPARQL**, ever.

## Risks carried into Phase 2

- **LLM dependency vs reproducibility.** Mitigated by design, not by hope: the deterministic floor
  always runs, escalation is ~14%, the cache is keyed by model + prompt version, and the provider
  sits behind an interface with a test fake. A cached re-run must work with the network off — that
  is an acceptance criterion, not a nicety.
- **Clustering may not be 1:1** (and may not be the right primitive at all). Probe F runs *first*,
  and it tests the cheap work-order-code hypothesis before any parameter tuning.
- **Diameter-class equivalence is a legal reading**, transcribed by hand from CVDR697591. It needs
  per-rule article sourcing and human review; a wrong equivalence silently mis-sizes every
  obligation.
- **Absence of replant is not a violation.** Herplantfonds discharge is legitimate and not publicly
  observable → `fundEligibilityUnknown`, never a hard "violation" verdict. (The fund balance is a
  Phase-4 WOO request.)
- **Noord is a small slice for the fuzzy signals.** Species appear in 2.5% of Noord abstracts vs
  5.2% citywide, and projects in 0% of Noord vs 1.3% citywide — so species/project extraction will
  look thin locally. Validate those tiers against the **citywide** corpus (already landed: 10,503
  records) or the numbers will read as a failure when they are a sampling artifact.
- **Registry lag is a phenomenon, not a bug** — a replant filled in months later closes one
  assessment and opens another; that history *is* the product.
